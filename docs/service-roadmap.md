# 1RM Calculator Service Roadmap

이 문서는 1RM 계산기를 단순 계산 도구에서 지속 사용 가능한 운동 기록 서비스로 발전시키기 위한 실행 순서입니다.

## Product Direction

핵심 가치는 사용자가 "내가 강해지고 있는지"를 빠르게 판단하도록 돕는 것입니다. 계산 정확도, 기록 품질, 목표 추적, 데이터 보존성을 순서대로 강화합니다.

## Phase 1: Trustworthy Local App

목표: 로그인 없이도 완성도 높은 개인 기록 앱으로 사용할 수 있게 합니다.

- 1RM 결과에 신뢰도와 추정 범위를 표시합니다.
- 기록에는 세트 수, RPE, 메모, 운동 날짜를 저장합니다.
- 기록 수정과 삭제를 지원합니다.
- 계산/단위/목표/볼륨 로직에 자동 테스트를 둡니다.
- JSON 백업/복원은 기존 데이터와 새 데이터 형식을 모두 읽어야 합니다.

완료 기준:

- 사용자가 과거 운동을 입력하고 나중에 수정할 수 있습니다.
- 볼륨 계산은 세트 수를 반영합니다.
- 핵심 로직 테스트와 프로덕션 빌드가 통과합니다.

## Phase 2: Better Training Insight

목표: 차트를 보는 앱에서 해석을 제공하는 앱으로 개선합니다.

- 최근 4주 볼륨 변화율을 표시합니다.
- 종목별 PR 증가량과 마지막 갱신일을 표시합니다.
- RPE가 높은 기록과 낮은 기록을 구분해 피로도를 추정합니다.
- 목표일까지 필요한 평균 증가량을 보여줍니다.

완료 기준:

- 대시보드가 숫자 나열이 아니라 다음 행동을 판단할 수 있는 문장을 제공합니다.
- 분석 화면은 기록이 적을 때도 빈 차트 대신 유효한 안내를 제공합니다.

## Phase 3: Account And Sync

목표: 브라우저 로컬 저장 한계를 넘고 여러 기기에서 사용할 수 있게 합니다.

- Firebase Auth 또는 Supabase Auth로 로그인 기반 계정을 제공합니다.
- 로컬 기록을 계정 데이터로 마이그레이션하는 흐름을 둡니다.
- 오프라인 기록 후 온라인 복구 시 충돌 정책을 정의합니다.
- 사용자는 언제든 JSON 내보내기로 데이터를 소유할 수 있어야 합니다.

완료 기준:

- 새 기기에서 로그인하면 기존 기록과 목표가 복원됩니다.
- 로컬 기록이 있는 사용자가 로그인해도 데이터가 사라지지 않습니다.

## Phase 4: Service Operations

목표: 공개 서비스로 운영할 수 있는 기본 체계를 갖춥니다.

- 오류 모니터링과 핵심 이벤트 로깅을 추가합니다.
- 개인정보 처리 범위를 명확히 안내합니다.
- PWA 설치 경험과 오프라인 상태 안내를 정리합니다.
- 릴리즈 전 체크리스트를 문서화합니다.

완료 기준:

- 주요 기능 실패를 운영자가 확인할 수 있습니다.
- 데이터 저장 방식과 백업 방법이 사용자에게 명확합니다.

## Current Next Best Work

현재는 Phase 1의 로컬 품질 기반과 Phase 2의 기본 해석 기능을 구현했고, Phase 3 계정 동기화를 준비하는 단계입니다.

완료된 기반:

1. 백업/복원 데이터 스키마 검증 강화
2. 대시보드 최근 4주 변화 요약
3. 목표일까지 필요한 주간 증가량 계산
4. 분석 화면의 PR/RPE 기반 해석
5. 로그인/동기화를 위한 `createdAt`, `updatedAt`, `syncVersion` 메타데이터
6. Firebase Auth/Firestore 준비 모드와 로컬 모드 분리
7. 삭제 tombstone 기반 동기화 충돌 정책
8. PWA 오프라인 상태와 새 버전 업데이트 알림
9. 데이터 처리 안내 화면과 프로필 진입점
10. 배포 전 릴리즈 체크리스트와 환경 변수 검증 기준
11. 앱 내 출시 준비도 점검 화면
12. 운영 문의 이메일 기반 계정 데이터 삭제 요청 안내
13. 앱 내 런타임 진단 정보와 오류 경계
14. 첫 사용자를 위한 빈 상태 온보딩과 분석 CTA

다음 구현 우선순위:

1. 실제 Firebase 프로젝트 환경 변수 연결
2. Google 로그인과 Firestore 실동기화 QA
3. Firestore 에뮬레이터 기반 보안 규칙 테스트
4. 운영 문의 이메일 실제 값과 삭제 요청 처리 프로세스 확정
5. 외부 오류 모니터링 서비스 연결
